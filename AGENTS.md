# Project AI Instructions

## Project Context
Read `docs/PROBLEM_STATEMENT.md` and `docs/ARCHITECTURE.md` before implementing features.

## Team Coordination
- Read `docs/TEAM_ROLES.md`.
- Read the relevant member's role file before coding (`docs/MohitRole.md`, `docs/RohitRole.md`, `docs/GauravRole.md`).
- Read `SKILLS_SETUP.md` and activate the appropriate skills from `.agents/skills/`.
- Read `docs/WORKFLOW.md` and `docs/RULES.md`.
- Check `docs/TASK_BOARD.md` before starting a task.
- Respect the file ownership assigned to each member.
- Do not modify another member's module without coordination.

## Coding Rules
- Inspect existing code before creating or modifying files.
- Follow the existing architecture and installed dependencies.
- Do not invent API endpoints, schemas, or environment variables.
- Keep changes small and focused.
- Handle errors and validate user input.
- Never hardcode API keys, passwords, or secrets.
- Never overwrite another person's uncommitted work.
- Never use `git push --force` on the shared main branch.

## Before Finishing a Task
1. Run relevant tests and lint checks.
2. Review the changes for regressions.
3. Report changed files and commands executed.
4. Document anything that could not be tested.
5. Update the task status in `docs/TASK_BOARD.md`.

## AI Behavior
- Do not claim a feature works without verifying it.
- Do not replace working code just to rewrite it in your preferred style.
- Ask before making destructive changes or adding major dependencies.
- If requirements conflict, explain the conflict before coding.

## Working Protocol
1. Read `AGENTS.md` and `docs/TEAM_ROLES.md`.
2. Check `SKILLS_SETUP.md` for relevant domain skills.
3. Read `docs/WORKFLOW.md` and `docs/RULES.md`.
4. Check `docs/TASK_BOARD.md`.
5. Work only on assigned files unless coordinated.
6. Pull the latest `main` before integrating changes.
7. Test your changes before committing.
8. Report blockers and update the task board.
