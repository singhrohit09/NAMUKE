# Project Rules

- One task must have one clearly assigned owner.
- Shared interfaces must be agreed upon before implementation.
- Do not silently change API contracts.
- Do not delete or overwrite teammates' work.
- Do not commit `.env` files, credentials, or API keys.
- Update `.env.example` when configuration changes.
- Use meaningful names and consistent formatting.
- Test new behavior and important edge cases.
- Never claim tests passed if they were not run.
- Discuss major architectural changes before implementing them.
- Direct pushes to `main` are allowed, but coordinate first.
